# 通用 Reader：从卡片覆盖改为问题要求覆盖

本文件记录统计维度校验缺口的通用实现；需求契约、投影采集、去重分组和需求覆盖验收已于 2026-09-24 接入本机 Agent。知识材料统一位于 [artifacts/KB/](../../../navigation-knowledge/artifacts/KB/README.md)，作为 [现有页面目录](../../../navigation-knowledge/artifacts/page-catalog.json) 的附属说明；归档与测试缺口导出路径已同步。

## 1. 问题

现有 TaskSpec 已识别请求对象和分组维度，但 MeasureSelection 只枚举页面卡片。execute_analysis 又把允许输出的标签限定为选中的卡片，导致完整行集计算出的新分组被拒绝；输出与卡片数值一致却没有满足问题，也可能通过现有校验。

此外，计数粒度只是一段说明文本，缺少与实际身份键、去重步骤的结构化绑定；每轮页面观察覆盖上轮 sources，不能凭现有三次补读获得可靠的全队列集合。网关的展示证据截断也不能当作完整数据。

## 3. 需求绑定与验证

通用流程按“用户要求 → 检索到的语义定义 → 实际来源字段 → 计算步骤 → 输出证据”绑定。模型可以提出绑定，程序必须检查引用存在、字段与来源一致、数据范围完整、运算符合契约；不能把存在一条知识引用当成语义已经证明。

每个请求要求至少记录：稳定 ID、语义字段引用、计数单位、群体/范围、过滤与时间上下文、来源和字段路径、实现算子或等价聚合证明、对应输出、满足状态。自由文本中的“这不是去重申请数”不能代替请求粒度已满足的证明。

有可信结构化语义证明某个聚合正好对应请求时，可直接使用聚合。否则通过授权采集获得所需字段的完整集合，验证身份键，再执行 distinct/count/group_count 等通用算子。需要分组时不能只返回总数；不能把总数放进分组结果。

对重复实体不能无条件保留第一条。完全相同的重复记录可按已绑定身份键去重；同一实体出现冲突状态时，必须使用经验证的业务规则，缺少规则则返回语义缺口。分组标签来自真实字段值；只有知识明确给出分类全集时，才能补充未出现的零值分类。

## 4. 完整性和结果状态

分页必须保持相同身份、群体、筛选和稳定排序。只有采集覆盖证明充分时才执行全量计数；重读第一页、重复页、总数漂移、缺少标识、源响应截断、预算耗尽都不能伪装成完成。没有服务端快照能力时保留读取时间窗口和一致性限制，前后总数相同也不宣称事务级快照。

完整性不足可返回已观察的有限信息，但其角色应为 observation，不能标记为已满足的 total 或 breakdown。新增 requested_grain_unverified、requested_grouping_unfulfilled、collection_incomplete 等明确原因；部署绑定问题单独记录，不应遮盖分组要求未完成。

## 5. 知识与流程边界

页面集合、身份和路由由 [现有页面目录](../../../navigation-knowledge/artifacts/page-catalog.json) 统一维护；目录内页面的只读操作候选、字段映射、分组含义、业务身份键及重复/冲突处理规则，补充到 [artifacts/KB/pages/](../../../navigation-knowledge/artifacts/KB/pages/)。代码只实现契约、权限、分页、字段投影、去重、计算和校验，不包含 L01 判断、固定状态名单或测试时的数字。

知识不足时按页面生成待核实清单，补入对应页面说明，不生成问题匹配或答案模板。权限、网络与通用能力问题保留独立类别；知识不能赋予接口执行权限。页面说明提供可检索的字段事实和语义关系，Agent 根据当次问题动态构建分析计划；知识中不预设某道问题的运算步骤或答案。单独导入页面说明不能消除代码中的卡片约束。

## 6. 实施与验收顺序

1. 先修需求/输出契约与缺项判断：让卡片代替分组的旧行为明确失败。
2. 接入知识语义绑定，重构来源选择与通用计算，去掉卡片标签对正确计算结果的限制。
3. 补齐获准分页采集、完整性证明、身份去重和冲突处理。
4. 统一回答与审计，并验证相关业务字段草案。
5. 用不同业务名称、字段名和分类值的合成案例验证流程；再以英文 L01 对当前完整队列独立核算。预期数值来自当次数据，不固定为历史数量。

验收要求是每个用户要求均有可核验结果，或准确显示具体未满足原因；不是只看 turn.completed、卡片相等或缺口 JSON 是否成功输出。


## 7. 本次落地与验证

- `reader_requirements.py` 生成稳定要求 ID，绑定来源、字段、实际计算依赖和输出；验收输出 `requirementsSatisfied` 与逐项 `requirementCoverage`。存在卡片不再强制覆盖全部卡片，也不限制新计算结果的标签。
- 业务含义必须引用 active 的页面字段绑定；精确核对概念/别名、只读操作、行数组路径和字段。普通文字引用只供定位与候选判断，不能充当实体或维度证明。范围/群体还按参数哈希核对 `contextParameters`，防止把有筛选的集合当成全队列。
- 网关复用本次页面已触发且白名单许可的请求，只改变页码；同身份、同筛选、同排序完成两次有界扫描。禁止重定向；记录上下文、页数、总数、投影摘要与时间窗口。缺页、重复页、数据漂移、超限、缺失标识均不能返回完整集合。
- `reader_collection.py` 对完整集合使用独立传输边界，不受展示样本条数限制；损坏或截断的回执直接失败。模型只接收字段目录和采集回执，程序处理所需真实字段。
- 相同实体完全一致时去重，冲突时不保留第一条。支持组合维度分组；总数与分组必须消费同一个过滤、去重后的集合。超过输出上限明确失败，禁止静默丢组。
- 明细或分组计算与问题不对应时不能标为满足；卡片及其他缺乏证明的数值标记为 observation。业务结果、知识缺口、运行失败和部署版本限制分别记录。

真实网关检查已经取得完整当前队列并按实际字段计算，详细结果保存在测试报告中。Agent 英文实测仍未完成业务验收：现有远程检索内容尚不足以证明实体、分组和分页字段。需要维护的是页面定义及术语，不是在流程中添加 L01 路由或答案规则。

当前采集支持页码分页和标量字段投影；游标分页、嵌套字段投影、日期范围的结构化契约、复杂冲突归并以及聚合接口的语义等价证明尚未实现。双遍一致不等同于事务快照；部署版本未核实时仍明确标记限制。
