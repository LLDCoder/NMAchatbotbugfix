# 页面路由绑定说明

## 1. 维护对象

路由绑定是既有页面的知识说明，描述入口参数、可识别的业务编号、视图名称和从列表记录到详情参数的对应关系。它放在现有知识包的 `record.payload.routing` 中；页面集合仍由 `artifacts/page-catalog.json` 决定。文件名称采用“页面名-知识范围.json”，例如“页面名-视图与详情入口.json”。不得写入问题编号、预期答案、实时数量、账号或固定业务记录。

知识包和有效记录使用 `active`。上传远端知识库、解析完成并可检索后，流程自动读取，无需额外发布开关。尚未验证的字段保留在页面维护清单中，不填写猜测值。交换包仍遵循 [知识包 Schema](knowledge-package.schema.json)，`payload.routing` 遵循 [路由绑定 Schema](routing-bindings.schema.json)。

## 2. 通用结构

| 字段 | 页面知识含义 | 运行时约束 |
| --- | --- | --- |
| `parameters` | 页面接受的参数、参数来源和是否必填 | 参数名必须在现有页面目录中；禁止任意 URL 或脚本 |
| `parameters[].from=recordIdentity` | 入口参数直接使用用户提供的业务编号 | 不得用于把业务编号当成内部数据库 ID |
| `parameters[].from=previous_record` | 参数来自前一只读页面已观察记录的字段 | 必须同时声明来源接口、行路径、业务编号字段、主键字段和目标取值字段 |
| `records` | 当前页面响应中定位业务记录的方法 | 当前权限、成功且获准的响应、业务编号一致、内部标识唯一 |
| `views` | 视图标识、显示名称及页面自身的别名 | 当前页面的唯一选中视图必须匹配；浏览器提示不能替代观测 |

`operationRef` 使用实际观测中的方法与路径；`sourcePath` 为响应 `data` 内的 JSON Pointer；`identityField` 是业务编号字段；`keyFields` 标识实体；`field` 是传给下一入口的字段。`unique=true` 只在页面数据模型已证明该业务编号唯一时填写。没有完整采集证明、也没有唯一性定义时，流程不宣称记录定位成功；普通分页响应没有被截断，也不等于完整数据。全量采集替换数据后会重新校验页面、参数、视图和记录，旧样本的证明不能沿用。

每个定义必须有页面内唯一 `id`。模型使用的绑定标识由程序生成：`record.id#definition.id`。页面知识不能授权新接口、放宽权限或执行业务写操作。

## 3. 来源与缺口

记录的 `sources` 应能追溯源码、手册或授权页面观测，并给出版本。字段范围、个人/团队含义、查询默认值和分页定义仍由 [字段绑定说明](字段绑定说明.md) 维护。路由成功并不意味着这些要求已经通过。

读取后分别核验最终页面、参数摘要、当前视图和业务记录。范围、实体粒度、筛选、时间及统计字段继续进入需求覆盖验收。缺少对应定义时输出页面维护 JSON；所有待补项归集至 `KB/pending/`，不能将某次测试问答直接作为页面知识导入。

远端 JSON 被切块时，当前加载器在同一目录范围内按文档 ID、顺序、连续重叠、大小及 JSON 完整性重建，并检查前后文件版本。它最多处理 3 份、每份 1 MiB 的文档；每份最多增加文件名查询和一次边界续检。缺块、更新冲突或预算耗尽时保留缺口，不把碎片降级为可执行知识。该检查不是上游事务快照证明。
