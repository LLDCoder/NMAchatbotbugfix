# 页面字段绑定格式

页面说明继续描述页面、视图、实体、字段、只读操作及适用版本。本次增加 `field_semantics.payload.bindings`，让程序能够核验字段归属和计算粒度；不写问题编号、问题匹配条件、回答模板、固定分类或历史统计值。结构见 [field-bindings.schema.json](field-bindings.schema.json)。

每条绑定定义一种页面事实：`kind` 为对象、实体粒度、范围、群体、维度、过滤、时间、属性（attribute）或指标（measure）；`concept` 为规范业务术语，`aliases` 为经过确认的中英文同义名称；`operationRef` 为实际响应来源；`sourcePath` 是从完整响应根开始的行数组或详情对象路径；`fields` 是该含义对应的字段名。粒度定义使用完整实体身份键，维度定义使用真实分组字段。不同视图或接口的同名字段应分别定义。

范围和群体事实还需提供 `contextParameters`：所有影响数据范围的请求参数及其已核实值。网关只输出参数摘要哈希，验收器据此核对默认筛选；分页和排序参数不改变完整采集后的总体。遗漏参数、不同筛选值或缺少定义都会保持范围未确认，避免把当前筛选后的集合当成全队列。

绑定 ID 在运行时是 `record.id#binding.id`。Agent 依据当次问题引用页面绑定，生成计算计划；程序检查操作、路径、字段与请求概念的对应关系，再核验计算依赖和输出。仅引用一段出现相关词语的文字不足以证明字段含义。跨语言名称须在页面术语中明确对应，不使用模糊关键词猜测。

`bindings` 与字段说明、分页说明配合使用。采集定义应在 `payload.sourceBinding` 写明 `operationRef` 和 `sourcePath`，在 `payload.fields` 说明实际字段，在 `payload.pagination` 写明 `rowsPath`、`totalPath`、页码和页大小参数；请求参数也可在 `payload.requestFields` 中说明。程序根据当前页面、操作和行路径编译已启用的结构化定义，并与本次观察到的响应字段及请求参数核对。模型引用原文作为补充证据，不再要求每次引用重复列出全部已加载字段。结构定义证明如何采集，业务范围、实体粒度和计算口径仍由 `bindings` 及需求验收独立核实。采集只调整网关已观察并核实的页码与每页条数参数，不能新增接口权限或替换筛选参数。

列表到详情的定位步骤只采集记录标识和下一跳所需参数；详情字段留到最终来源读取。业务编号未被证明全局唯一时，需要完整定位集合，不能把第一页中的唯一匹配当作全局唯一。

详情字段说明必须绑定详情操作及实际对象路径，不能直接复用列表操作的字段绑定。TaskSpec 已分开使用 requestedAttributes 和 requestedMeasures。网关生成逐字段完整性与值哈希回执，后端核对来源、记录和目标字段；记录身份通过不等于所有属性完整。有效绑定的记录引用由程序补齐，不要求模型复制整段 JSON；用户要求仍必须通过实际输出分支验收。未展示的旁支不能作为回答证据。

供远端知识库导入的文件直接使用 `packageStatus=active`、`records[].status=active`。上传远端并可被检索后即可参与流程，无需再手动切换发布状态。业务术语、部署适用性与来源的核验信息另行记录在 `applicability`、`sources` 和 `constraints` 中。检索应能返回完整、独立的 `field_semantics` JSON 记录包及页面说明；不要将一个记录拆为无法解析的 JSON 片段。页面绑定可以按视图拆成小记录。不同版本发生冲突时，程序拒绝混用。

当前版本支持页码分页、顶层及嵌套标量字段投影、实体去重、组合维度计数、计数与求和。嵌套标量使用点路径，例如 `sla.isOverdue`；字段说明须包含实际层级名称。对象、数组不作为普通标量投影。父对象为空时保留 `null`，不能据此认定其子字段为否；叶字段不存在时报告字段缺失。unknownPolicy=report 可保留已知结果并附未知项，缺字段或未知筛选值不会被判为完整答案。游标分页、含冲突实体的业务归并以及聚合接口与明细粒度的等价证明尚不支持；不能用知识文档宣称这些能力已实现。没有结构化等价证明的卡片只可作为观察值。

采集最多 5,000 行、每轮 100 页、两轮响应累计 5 MB。网关仅调整已观察并核实的分页字段：页面原每页条数小于 100 时，完整采集使用 100；原值较大时保持原值（已观察值最大 500）。两轮固定相同的每页条数，身份、筛选与排序上下文保持不变，并比较所需字段。回执记录原每页条数和实际采集条数；服务器截断、忽略分页大小或返回不完整页面时拒绝完整性结论。它提供有界一致性校验，不表示数据库事务快照。计算分组最多展示 200 组，超限明确报告，不静默截断。默认分类来自真实数据；includeZeroGroups 仅在同操作、路径和维度的有效绑定明确声明 values 领域时，为单维度补零。

## 条件指标、时间与表单

业务指标使用 kind=measure，operator 为 count 或 sum，conditions 显式声明字段、比较符和值；sum 还需 valueField。字段必须属于同一绑定。代码执行条件与去重、分组，知识解释条件的业务含义。多个指标按各自过滤后总体逐项验收，不能用全体分组证明另一个条件指标。布尔值与数字不等价；null 不等于 false。普通计数无需制造业务指标记录：对象和总体已分别证明时，程序可执行 count。

时间绑定使用 kind=time，明确日期字段的业务含义；TaskSpec.timeField 指定概念，timeRange 指定区间。filter_time 支持今日、上／本周月年、最近／未来 N 小时天周及显式日期区间，内部采用左闭右开边界。没有时区的源时间必须在知识中给出已核实的 sourceTimezone；不能使用开发电脑时区猜测。dateOnlyBoundary 可明确仅日期字段的日末语义。参考时刻、业务时区和实际起止值写入证据。

表单属性可提供 formDefinition，format=schema_values/1，并指定 recordPath、versionPath、documentPath、schemaPath、valuesPath、containerPath、componentKey 和 materialComponents。程序从已验证详情记录的有界 JSON 文本读取 schema 和 values，不执行脚本或读取附件正文。支持静态必填及声明式相等／不等条件；动态脚本、未声明的外部显隐规则和适用版本未确认时保留 unknown。applicabilityComplete=false 表示适用性尚未完整核实，不能据此生成肯定的缺失材料名单。

维护故障 JSON 与有效页面事实分开：超时、计划错误、能力限制、权限或验收失败不能直接作为页面知识导入。补充后的事实文件使用“页面-知识范围.json”命名、active 状态、可核验来源和版本；不包含用例编号或历史答案。


### 同一记录内的实体定义组合

当 object 与 grain 的规范概念、operationRef、sourcePath、实体字段、contextParameters 和 conditions 全部一致时，通用编译器允许 grain 复用同一 active 记录中 object 已声明的别名，并记录 aliasEvidenceBindingIds。无需为一个测试问题重复添加别名；跨页面实体或范围的等价关系仍必须在知识中有独立依据。

表单材料判断还要求 formDefinition.applicabilityComplete 明确为 true。未核实服务显隐规则时应设置 false，结果会报告知识不足；不能为得到完整答案而把此字段改为 true。

表单版本尚未核实时，formDefinition.versionPath 显式为 null。服务标识不能充当表单版本；执行器应返回 form_version_unverified，不能根据服务编号确认材料缺失。只有来源已验证的版本路径、当前记录和完整适用条件同时满足，才可确认材料状态。
